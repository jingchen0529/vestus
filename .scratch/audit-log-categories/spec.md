# 审计日志中文展示与分类

Status: 已实现（自动测试与构建通过；完整乱序和窄屏浏览器验收待完成）

## 目标

- 动作类型与操作摘要合并为一列「操作内容」，显示中文动作、分类标签和原始摘要。
- 保留一个审计菜单，按「管理端登录 / 管理端操作 / 桌面端登录 / 桌面端操作 / 系统操作 / 来源不明」筛选。
- 同步更新列表、详情和导出；不修改桌面配置刷新、Q&A 或登录认证规则。

## 分类契约

`GET /api/admin/user-logs` 新增可选 `category` 参数，取值：

| 值 | 中文 | 规则 |
| --- | --- | --- |
| `admin_login` | 管理端登录 | 管理员的 LOGIN、LOGOUT；明确来自管理员登录入口的匿名失败登录 |
| `admin_operation` | 管理端操作 | 管理员的其他事件（包括配置桌面用户、帮助内容） |
| `desktop_login` | 桌面端登录 | 桌面用户的 LOGIN、LOGOUT；明确来自桌面登录入口的匿名失败登录 |
| `desktop_operation` | 桌面端操作 | 桌面用户的其他事件，包括改密、托管登录票据、读取配置和帮助 |
| `system` | 系统操作 | system 主体的非登录事件 |
| `unknown` | 来源不明 | 旧匿名登录、兼容入口匿名登录及无法识别的主体 |

- 已识别主体 `admin/user` 优先，不按事件前缀、目标对象、摘要或 User-Agent 猜来源。
- 两个独立登录入口在 `details.authSource` 中写入服务端确定的 `admin/desktop`；用户提供的同名字段不起作用。
- 未知账号仍是无 ID 的 system 主体，不虚构身份。兼容登录入口无法确定端来源时不填此字段。
- 保留原有 `details.deviceId`、英文 `action`、摘要及所有历史记录；无需数据迁移。

## 读写与权限

- 在统一 `log_dict()` 追加 `actionLabel`、`category`、`categoryLabel`，旧接口和详情保持一致。
- 分类条件在数据库 COUNT、分页前执行，并与既有可见范围和其他条件取交集。
- 普通管理员不会因为匿名登录补来源而扩大可见范围。
- 未知事件在列表显示「其他操作」；原事件代码留在详情与导出。
- 切分类或结果回第一页，避免旧请求回写；全量导出的每一页沿用同一筛选。

## 验证边界

1. 通过日志 service 的公开查询接口验证中文名称、四种主要分类、历史未知事件、计数分页和权限范围。
2. 通过隔离 SQLite HTTP API 验证分类参数、登录失败入口、详情与兼容端点一致、保留设备标识。
3. 实际 React 渲染和 API mock 测试验证中文合列、详情及导出。
4. 本地隔离 fixture 页面验证筛选、分页、请求乱序、详情和窄屏，不接真实客户数据。

# Vestus desktop-v0.2.16 版本说明

## 发布信息
- 目标环境：dev 测试环境，不是生产环境。
- API 地址：`https://vestus-dev.quanyuos.com`
- 对比版本：上一成功发布版本 `desktop-v0.2.15`。
- 本版用于安装验证 Windows 首次打开浏览器后切换应用的反馈；使用新标签 `desktop-v0.2.16`，不移动历史标签。
- 按现有流程构建 Windows x86_64、macOS Apple Silicon / Intel、Linux x86_64；Windows 产物完成后优先提供下载，四平台全部成功后发布 GitHub Release。本次不部署服务器、不执行数据库迁移或历史回填。

## 本次更新
- 修复客户端获得焦点、手动刷新或重复同步配置时，未经配置比较就先关闭全部外置浏览器的问题。同一登录、同一有效配置的刷新保留浏览器会话、代理端口和看门狗，只更新展示信息。
- 合并并发刷新、隔离旧登录的迟到响应；同步失败不再继续自动重开浏览器或提示成功。配置变更事件在当前请求结束后仅排一次补充同步。
- 桌面服务网络/服务器临时错误只提示并重试，不再连续三次失败就按登录失效销毁会话；仍受已知 JWT 与用户授权截止限制，不延长授权。
- 退出客户端、主动退出登录、明确撤权、真实配置租约变化、托管登出及安全监控故障保留清理。配置切换/看门狗清理未确认时，阻止新配置和新浏览器启动，支持解除占用后重试。
- 增加有界本地浏览器关闭原因日志，不记录 Cookie、令牌、密码、完整网址或 profile 路径。
- 包含上一版之后已合并的更新：密码字符集规则对齐，以及托管活动上报绑定实际启动票据；仓库同时包含后台自助改密和广告账户访问索引，须配套后端部署才生效。
- 增加构建 API 与本版说明的一致性检查；实际配置不符时停止打包，防止 dev 包误连其他环境。

## 安装与升级
- Windows x86_64：下载并运行 `Vestus-0.2.16-windows-x86_64.exe`，先退出旧 Vestus 及其浏览器，再覆盖安装。未提供 Windows ARM 原生包。
- macOS Apple Silicon / Intel：选择对应架构 `.dmg` 并复制到「应用程序」；未做 Apple 开发者签名和公证。旧于构建系统的兼容性未实机验证。
- Linux x86_64：使用 `.deb` 或可执行 `.AppImage`；当前未启用系统钥匙串持久化，重启客户端需重新登录。
- 使用 dev 桌面用户账号。安装后重点验证首次打开、切换第三方应用、切回 Vestus、最小化/恢复、超过 60 秒再次切换及退出清理，步骤见 `docs/browser-background-testing.md`。

## 后端配套
- 浏览器刷新保活修复不新增后端接口或数据库迁移。
- 本次完整桌面代码包含托管活动上报的 `bootstrapSessionId` 字段，完整配套需部署含 `c7853df`、`e5a3edd` 对应功能的后端，并完成迁移 `0018`。顺序：备份并迁移、升级全部后端实例、按需另行批准历史回填、最后升级桌面端。
- 旧 `b80d007` / 迁移 `0017` 后端可能以 422 拒绝新的托管上报，不能宣称完整兼容；其非托管路径不受该新增字段影响，可做有限保活验证，但不能代替托管上报联测。
- 当前 dev 后端实际版本、迁移状态未远程核实；本次仅发布桌面包，不代为部署、迁移或回填。

## 验证结果
- 本地前端测试 149 项通过，包含发布 API 一致性新增回归；前端构建、能力边界检查及 diff 格式检查通过。
- 本地 Rust 回归 290 项通过、0 失败、4 项需显式环境的测试默认忽略；生产代码 `cargo check --locked --lib` 通过。
- 在 macOS Apple Silicon 上显式执行隔离 Chromium 控制验收和持久化矩阵，均通过。配置同步专项覆盖真实受管子进程保留、撤权/退出终止、清理失败阻断与重试。
- 严格 Clippy 未通过：未修改的 `cdp.rs` 有 `unnecessary_sort_by`、`derivable_impls` 两项既有提示；本次新增代码的静态检查问题已修正。现有 Release 没有 Clippy 门禁。
- 本次四平台远端构建、Windows 安装与真实 Alt+Tab 场景尚未验证；发布安装包后由实际安装测试补齐，不能将 macOS 或纯 Chromium 检查当作 Windows 验收。

## 已知限制
- 已修复确定的焦点刷新关闭链；只从浏览器切到第三方应用、从未激活 Vestus 的完整现场触发链尚未真机复现。若仍发生，使用本地关闭原因日志进一步定位。
- 管理员修改名称/排序等若改变现有服务端 lease，仍可能重建浏览器；本次未实现所有配置的热迁移。平台 Cookie 是否继续有效仍由平台决定。
- 用户到期时间按服务端已下发数据校验；当前用户视图通常只有日期，客户端无法恢复未下发的日内时刻。
- Windows 标准日志位置为 `%LOCALAPPDATA%\com.zhixi.vestus\browser-lifecycle.log`，文件最多 256 KiB、队列有界；磁盘/锁/队列错误可能丢诊断，不影响清理，无日志不证明未关闭。
- 四平台真实控制测试保持阻塞；Windows 持久化检查沿用非阻塞策略，须看具体日志。Windows 产物可先从 Actions 下载，正式 Release 仍等待四个平台成功。

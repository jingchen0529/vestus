# Vestus desktop-v0.2.20 版本说明

## 发布信息
- 目标环境：dev 测试环境，不是生产环境。
- API 地址：`https://vestus-dev.quanyuos.com`
- 对比版本：上一成功发布版本 `desktop-v0.2.18`；包含未完整发布的 `desktop-v0.2.19` 改动及本次 Windows 测试启动修复。
- 使用新标签 `desktop-v0.2.20`，保留 `desktop-v0.2.19` 和全部旧标签。说明批准后与修复代码一起提交，由该提交触发四目标构建，全部成功后发布 GitHub Release。
- 仅推送代码并发布桌面安装包，不部署后端，不执行数据库迁移或回填。

## 本次更新
- 修复 Windows 真实 Chromium 测试的启动准备：控制与持久化 fixture 在启动随包浏览器前，复用现有沙箱 ACL 命令，为三个既有沙箱 SID 补齐读取/执行权限。权限命令失败或返回非零时在启动前报错并输出诊断，不再等到页面地址超时。
- 权限准备仅作用于经过真实路径检查的本仓库随包 Chromium；执行递归授权前拒绝资源根及后代中的符号链接和 Windows reparse point，防止授权越界。外部覆盖路径和系统浏览器不改权限，非 Windows 不执行 ACL 命令。保留安装器和生产运行时原有权限策略，不增加写权限、不关闭沙箱、不跳过真实门禁。
- 保留 0.2.19 的地址专用采集：仅记录顶层标签页地址、脱敏查询参数、访问次数及必要元数据，保留 `advid`。不再采集 input/change、表单快照、点击、提交、滚动或停留时长；删除活动采集脚本、心跳、binding 和无用 Runtime 日志订阅。
- 保留初始地址、SPA、iframe 排除、弹窗/新标签页及托管登录截止时间的时序修复；固定登录防护、代理、沙箱及 SQLite FULL/容量回滚保障不变，历史队列按原内容补报。
- 随包内核继续精确锁定 Chrome for Testing Stable `157.0.8103.78`（revision `1717349`），保留官方下载、架构/版本/归档校验与失败回滚，不默认禁用 GPU。
- 保留已合入的托管会话失效和自动登录审计代码；其后端功能需另外部署，本次不代为部署。

## 安装与升级
- Windows x86_64：保存未提交的平台操作，退出旧 Vestus 及其浏览器，再安装 `Vestus-0.2.20-windows-x86_64.exe`。没有 Windows ARM 原生安装包。
- macOS 按 Apple Silicon / Intel 选择 `Vestus-0.2.20-macos-aarch64.dmg` / `Vestus-0.2.20-macos-x86_64.dmg`；未签名公证，旧系统兼容性未实机验证。
- Linux x86_64 使用 `Vestus-0.2.20-linux-x86_64.deb` 或 `.AppImage`；原有重启后需重新登录的限制保留。
- 不清理真实 profile、登录存储或未确认队列。旧二进制备份不保证已升级 profile 可以直接降级，回退需先隔离验证。已安装的客户程序不会自动替换为本版。

## 后端配套
- 本次权限准备、地址采集和内核更新不增加生产上报协议或数据库迁移。继续使用 `/api/user/browser-activity/v2` 和原 batchId/owner/ACK 语义。
- 后端仍需支持 `bootstrapSessionId` 和迁移 `0018` 以来的身份快照；缺少兼容性的旧服务端可能返回 422。dev 当前实际部署/迁移状态未远程核实。
- 托管审计增强需要包含 `bac5ddf` 的后端代码，不新增迁移；本次仅发布桌面，不部署后端。
- 构建必须核对实际 API 与本说明一致，不读取仓库 Secret 明文，不匹配时停止构建。

## 验证结果
- 0.2.19 远端结果：发布说明、内核准备和常规测试通过；macOS 双架构及 Linux 构建成功。Windows 真实控制为 1 通过、1 失败，日志明确记录沙箱访问 `chrome.exe` 被拒绝（0x5）及网络服务崩溃；Windows 安装包未生成，GitHub Release 被跳过。
- 本次 ACL 回归先失败后通过；新增 5 项本地测试覆盖准确 SID/RX 参数、命令启动失败、非零退出诊断、成功路径、外部目录及资源树链接边界。Windows reparse point 的实际执行仍未验证。
- 修正真实浏览器测试的自身时序：登录、交互拦截和跳回业务页在同一页面任务内完成，避免多次调试连接占用生产 4 秒窗口；保留登录时锁定、跳离后释放、完整 4 秒无误报及安静登录超时验证，未放宽生产截止时间。
- 最终本机两轮桌面测试各 169 项通过，Rust 完整回归各 306 项通过、0 失败、5 项默认忽略；desktop 类型检查/构建、能力边界、Rust 格式与 diff 检查通过。
- 最终当前随包 CfT 157 的真实控制、地址采集与托管防护两轮各 2 项通过、0 失败、0 忽略，耗时 72.83 秒和 72.49 秒。测试为 macOS ARM64、新 profile 和 localhost；不等于 Windows ACL 执行已验证。
- 本次未改变后端或管理端运行代码；合并轮已有后端 491 项、管理端 127 项两轮通过。本次不将旧测试结果冒充 Windows 修复后的执行结果。
- 0.2.20 的远端 Windows ACL 执行、四平台构建、持久化结果、安装包安装与客户真实素材选择均未验证。新标签构建启动后须核对实际结果；失败不得跳过或改成成功。

## 已知限制
- 这次修复针对已确认的 Windows 测试环境权限缺失，不代表客户素材卡死的根因已确诊；客户 GPU/驱动、内存、高分辨率预览及网络问题仍未验证。
- Windows 持久化门禁仍沿用现有非阻塞策略，须单独检查日志与结果；本版给持久化 fixture 也补充独立权限准备，但不能提前宣称其通过。分发客户前应由开发/QA 验证确切候选包。
- 生产安装器和运行时原有 ACL 准备行为保留；本次仅复用命令并完善测试准备，不扩大生产权限、不改异常时的生产启动策略。
- 地址采集仍有 64 条首次 SPA 候选缓冲上限；持续就绪 CDP 事件可能推迟截止时间通知。初始托管 bootstrap 与 guard 安装间的继承时序、异常通道完整恢复未扩大修改。
- 旧队列可继续补报已有交互数据；降级到不支持稀疏记录的旧客户端可能暂时无法消费新队列，不能清库掩盖。
- 本版连接 dev API，不面向生产。构建成功与测试通过不等于客户场景已全部验收；未验证项目以新构建和安装测试的实际结果为准。

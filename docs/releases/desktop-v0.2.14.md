# Vestus desktop-v0.2.14 版本说明

## 发布信息
- 目标环境：dev 测试环境，不是生产环境。
- API 地址：`https://vestus-dev.quanyuos.com`
- 上一成功发布版本：`desktop-v0.2.12`；本版包含未成功发布的 `desktop-v0.2.13` 更新及此次浏览器控制测试修复。
- 使用新标签 `desktop-v0.2.14`，不移动或覆盖已有 `desktop-v0.2.13`。
- 本次仅提交并打包桌面端，不部署服务器，不修改生产或 dev 数据库。

## 本次更新
### 浏览器控制测试及发布可靠性
- 删除硬编码 macOS 系统 Chrome、访问外网 example.org、缺浏览器时静默通过的旧测试夹具；改用随包 Chromium、本地回环页面和独立临时 profile。
- 端口文件出现后，先在总启动期限内确认 Browser.getVersion 和 Target.getTargets 可响应且本地目标已存在，再执行激活、不匹配和同域复用断言。
- 正式激活断言不自动重试，生产控制命令三秒超时不变；就绪检查期限不等同于放宽生产超时。
- 新增全平台阻塞式浏览器控制验收：显式执行一个真实浏览器测试；缺浏览器、零用例、忽略用例、命令失败或信号退出均不能通过。Linux 使用 Xvfb。
- 增加版本、目标列表、就绪阶段及耗时诊断；测试退出时清理受控进程树，失败时输出测试专用浏览器日志。
- 跨进程 profile 锁测试显式解锁测试持有的文件，并保留重复句柄验证释放结果，避免 Linux 并发 fork 短暂继承句柄时仅靠 close 造成 Busy。生产锁机制不变。
- 后端凭据必填校验合并等价条件，兼容 CI 新版 Ruff 的 SIM102 规则，不改变认证和恢复行为。

### 包含 v0.2.13 的配套更新
- 身份校验采用有效、失效和无法确认三态，最近检查状态、时间及脱敏原因单独展示；网络问题不直接认定 Cookie 过期。
- 托管租约排除检查记录和纯展示元数据，保留凭据、授权与会话变动的失效机制，修复校验超时导致客户端误关浏览器的问题。
- 账号密码托管由服务端强制自动恢复；管理员写入接口不再接受 autoRelogin/auto_relogin，响应字段保留。Worker 配置关闭时，需要重新登录的请求明确失败。
- 审计日志增加中文动作和六类筛选，列表、详情及导出保持原有权限范围。
- 发版前必须展示并确认版本说明，构建检查同一提交的说明文件，GitHub Release 使用该文件；手动构建只产生 Actions 产物。

## 安装与升级
- Windows x86_64：运行 `.exe` 安装包。
- macOS Apple Silicon / Intel：选择对应架构 `.dmg`，将应用复制至「应用程序」。未做 Apple 开发者签名和公证，首次打开可能需要在系统安全设置中允许。
- Linux x86_64：使用 `.deb` 或给 `.AppImage` 执行权限后运行。客户端令牌未启用系统钥匙串持久化，重启后需重新登录。
- 安装前退出旧客户端及托管浏览器窗口；使用 dev 后台分配的桌面用户账号，不使用管理员账号登录桌面端。
- 后端租约算法升级可能使已有客户端旧租约失效一次，需重新同步配置；本次不再进行服务器升级。

## 后端配套
- 使用已部署的 dev 后端 `b80d007`，数据库迁移已在上一轮部署中升级至 `0017`，本版不新增后端迁移。
- `0016` 增加身份检查记录字段；`0017` 将历史密码托管恢复标记统一开启，不修改凭据和恢复终态。旧后端不能仅安装新客户端就获得这些管理能力。
- Web 管理页与移除恢复开关的后端须配套；旧页面提交 autoRelogin 会返回 422，需刷新管理页面。
- 自动恢复仍依赖服务端 Worker 与 Chromium 配置，不绕过上游验证，不无限尝试错误密码。

## 已知限制
- 已定位旧测试的系统浏览器选择、外网依赖与启动就绪缺陷，但尚未在 Intel runner 证明此前两次超时的具体底层原因或修复结果。
- 新控制测试在四平台全部阻塞；若 Intel 或其他目标失败，停止发布并根据诊断定位，不跳过门禁。
- Windows 持久化测试仍沿用既有非阻塞策略，与本次新增的阻塞式控制测试不同；发布成功不能替代持久化步骤的实际结论。
- 普通 Chromium 登录防护不是对恶意本机用户的安全隔离；验证码、滑块、二次验证及账号限制仍可能阻塞自动登录。
- 无身份探针的平台，其已失效 Cookie 无法仅靠未经验证的替换恢复。

# Vestus desktop-v0.2.13 版本说明

## 发布信息
- 目标环境：dev 测试环境，不是生产环境。
- API 地址：`https://vestus-dev.quanyuos.com`
- 对比版本：`desktop-v0.2.12`。
- 后端部署范围：仅 `guonei:/data2/www/vestus-dev` 与 `vestus_dev` 数据库；不部署到 `/data2/www/vestus`，不修改生产服务。
- 本次主要更新后端、管理后台和发布流程；桌面客户端业务代码与上一版本相同，以新版本号重新打包。

## 本次更新
### 托管身份校验
- 区分确认有效、确认失效和无法确认；网络超时、权限不足或未知响应不直接认定 Cookie 过期。
- 管理后台显示最近检查的状态、时间和脱敏原因，检查失败不会覆盖历史成功检查时间。
- 修复校验记录更新误触发桌面租约失效的问题。检查结果、时间和显示信息变更不再引起误关；凭据轮换、确认会话失效、授权范围变更、停用和解绑仍会使租约失效。
- 手动检查旧 Cookie 不会复活已失效会话；已失效 Cookie 更换后需验证成功才能恢复。

### 账号密码托管强制自动恢复
- 移除管理员写入请求中的 `autoRelogin` / `auto_relogin` 参数，服务端按账号密码模式强制开启自动恢复；响应状态字段继续保留。
- 新建或保存新凭据自动进入恢复队列，只有验证登录成功才更新 Cookie 并恢复有效状态。Cookie 导入模式不自动重登。
- Worker 配置关闭时，需要新登录的请求明确返回 503；已有可复用有效会话和仅修改别名不因此被拒绝。
- 保留三次尝试上限和退避策略，普通展示信息编辑不清零失败次数、不重新启动失败任务；真正停用账号仍取消待执行任务。

### 审计日志与发布说明
- 日志增加中文动作名称与六类筛选：管理端登录、管理端操作、桌面端登录、桌面端操作、系统操作、来源不明。
- 列表、详情及导出保持分类一致，保留原事件代码，不扩大普通管理员的可见范围。
- 后续打包须先展示版本说明并取得明确确认；构建前检查同一提交的说明文件，GitHub Release 正文直接使用该文件。手动构建必须填写版本号，只产生 Actions 产物，不发布 Release。

## 安装与升级
- Windows x86_64：运行 `.exe` 安装程序。
- macOS Apple Silicon / Intel：分别使用 `macos-aarch64.dmg` / `macos-x86_64.dmg`，将应用复制到「应用程序」。安装包未做 Apple 开发者签名和公证，首次打开可能需要在系统安全设置中允许。
- Linux x86_64：使用 `.deb` 或赋予 `.AppImage` 执行权限后运行；客户端访问令牌未启用系统钥匙串持久化，重启后需重新登录。
- 升级前退出旧客户端及其托管浏览器窗口。新租约计算方式与旧方式不同，后端升级时已有托管客户端可能关闭浏览器并需要重新同步配置；建议空闲时升级。
- 本版连接 dev，使用 dev 后台分配的桌面用户账号；管理后台账号与桌面账号不同。

## 后端配套
- 先备份 dev 数据库，再在 `/data2/www/vestus-dev` 更新配套后端及 Web 管理页面，执行 `alembic upgrade head` 后重启 `vestus-dev`。
- 新增 `0016_managed_identity_checks`：增加三个可空检查记录字段，历史值留空，不伪造旧检查结果。
- 新增 `0017_require_password_recovery`：仅将历史账号密码托管的关闭标记归一化为开启，不改变凭据、会话有效状态、失败次数或恢复时间。该数据归一化降级时不自动还原历史关闭标记。
- Web 与后端须配套升级。旧页面若仍提交已移除的自动恢复参数，会收到 422；升级后重新加载后台页面。
- 服务端 Chromium 与自动恢复 Worker 必须配置可用；不更换现有 dev 的密钥、账号密码或数据库连接配置。

## 已知限制
- 自动恢复不代表绕过验证码、滑块、二次验证或账号限制；明确凭据错误或需人工验证时停止当前恢复任务，不无限提交登录。
- 无身份探针的平台或无法验证的 Cookie，已过期后不能仅靠更换 Cookie 直接恢复，仍按验证失败处理。
- Windows 真实 Chromium 持久化步骤沿用现有非阻塞配置；发布任务成功不等同于该步骤一定成功，应查看具体测试结果。
- CI 只验证说明文件格式和存在性，不证明用户在对话中确认过，也不能证明全部业务场景通过。
